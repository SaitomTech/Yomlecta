# 記事タブとホーム最新記事の設計案

2026-09-20。画面・データ・遷移の設計。実装は未着手。

## 目的と役割

プロジェクトを開かなくても、作成した記事を横断して見つけ、閲覧・作成再開できるようにする。

| 画面 | 役割 |
| --- | --- |
| ホーム | 動画から作成を始める。新しい記事と最近のプロジェクトへアクセスする |
| プロジェクト | 動画と記事をプロジェクト単位で管理する |
| 記事 | 全プロジェクトの記事を検索して開く |

記事の所属と保存先は既存のプロジェクトのまま。記事タブは横断一覧として設ける。

## ナビゲーション

- 順序は「ホーム」「プロジェクト」「記事」。既存の緑色の下線で選択を示す。
- AppHeaderへ `activeNav: 'articles'` と `onArticles` を追加する。
- 現状は980px未満でナビ全体が非表示になる。狭い幅ではヘッダーの下段に3項目を表示し、記事へ常に移動できるようにする。
- 画面遷移のナビなので `nav` と `aria-current="page"` を使う。

## ホーム

上から「既存の動画読み込みエリア」「最新の記事」「最近のプロジェクト」の順。

- 最新記事は全プロジェクトから最大3件。新規作成日時の降順で表示する。
- 「最新」は記事レコードの作成日時とする。閲覧や編集だけで並び順を変えない。
- 未着手の記事候補も含める。状態を示し、作成の再開にも使える欄にする。
- 見出しの右に「すべての記事を見る」。記事タブの初期状態へ移動する。
- 最近のプロジェクトは従来どおり最大3件。
- 記事はコンパクトな縦3行。タイトル、所属プロジェクト、状態、作成日時を表示する。
- 背景色、緑のアクセント、白い一覧面、罫線、角丸、文字組は既存ホームとプロジェクト一覧を踏襲する。

## 記事一覧

- 見出し「記事」と件数。補足「すべてのプロジェクトの記事をまとめて表示します」。
- 検索対象は記事タイトルとプロジェクト名。前後の空白を無視する。
- 状態フィルターは「すべて／未着手／作業中／作成完了」。初期値はすべて。
- 初版は作成日時の新しい順に統一し、並べ替えコントロールは設けない。
- 1件を1行とし、ホームと同じ記事行を使う。長いタイトルは最大2行、所属プロジェクト名を副情報にする。
- 所属プロジェクト名からプロジェクト詳細へ移動できる。記事を開くボタンと独立した操作にする。
- 初回30件、以降は「さらに表示」。検索とフィルターは全件に対して適用してからページを切り出す。
- 新規作成は既存ホーム／プロジェクトの導線を利用する。削除操作は既存のプロジェクト詳細に集約する。

## 記事詳細（閲覧画面）

追補: 記事一覧から開く画面を、既存の作成フロー内の「記事の生成・編集」と分ける。記事タイトルは状態によらず記事詳細へ遷移する。ホームの最新記事にも同じ規則を適用する。

上から次の順に配置する。

1. 共通ナビ。「記事」を選択状態にする。
2. 遷移元へ戻るリンク（記事一覧／ホーム／プロジェクト詳細）。
3. 記事タイトル。副情報として状態、作成日時、リンク付き所属プロジェクト名。
4. 操作列。主操作「記事を編集」、副操作「プロジェクト詳細へ」、補助操作「書き出す」。
5. 保存済みの要約があれば表示。
6. 保存済みの章立てを目次として表示し、章見出し・スライド画像・本文を読みやすい幅で表示。

- デスクトップでは目次を左、本文を中央に置く。狭幅では目次を本文上部の折りたたみにする。
- 要約・章立てがなければ省略し、保存済みの本文をスライド順に表示する。画面を開いたことによる自動生成はしない。
- 作成途中なら「作成途中の記事です」と表示し、保存済みの本文を読めるようにする。本文がなければ状態と作成開始／再開の案内を表示する。
- 「記事を編集」は既存作成フローの「記事の生成・編集」へ。未着手は「作成を開始」、作業中は「作成を再開」に置き換えて適切な工程へ進む。
- 完了記事の編集ボタン横に工程選択メニューを設ける。「範囲・切り抜きを調整」「スライドを調整」「文字起こし・OCRを編集」「記事本文を編集」を、実際に遷移可能な工程に限定して表示する。
- 範囲・切り抜き等による後続結果の無効化は既存の保存処理時に適用する。工程を開くだけでは結果を変更しない。
- 「プロジェクト詳細へ」は記事の所属projectIdに直接遷移する。元の一覧へ戻るリンクとは別に常設する。
- 「書き出す」は既存Export画面へ接続し、既存の遷移可能条件を満たすときに利用できる。
- 作成フローに入った後は「記事に戻る」で閲覧画面へ戻せる。本文位置を復元し、さらに一覧へ戻ったときも検索状態を維持する。
- 未保存の編集や生成・保存処理中の遷移は既存の保護規則に統一し、追加したプロジェクト詳細への導線にも適用する。

閲覧画面の表示部品は既存レビューと共通化し、記事データは共有する。モデル選択・生成・編集フォームは作成フローに置く。

## 設定への整理

ヘッダー右側の更新確認、自動確認、ライセンス表示は常設しない。設定アイコンから設定モーダルを開き、アップデート欄とライセンス情報をまとめて表示する。更新が見つかった場合も、インストール操作はこのモーダル内で行う。

## 表示スタイル

記事詳細の本文はHTML書き出しの見た目を基準にする。要約は淡い緑の見出し付きブロック、章見出しは左アクセントの帯、本文は代表画像と本文の2カラム、狭幅では1カラムにする。目次は記事詳細の左側に限って表示する。本文量によって画像と本文を上下に入れ替える特殊なレイアウトは使わない。

## 記事を開く・戻る

記事タイトル／「記事を見る」は記事詳細へ。次の表は一覧の作成操作と、記事詳細の主操作に適用する。

| 状態 | ボタン | 遷移先 |
| --- | --- | --- |
| 未着手 | 作成を開始 | 範囲調整 |
| 作業中 | 作成を再開 | 保存済みの最終工程。遷移可否の検証を行う |
| 作成完了（一覧） | 記事を見る | 記事詳細（閲覧） |
| 作成完了（詳細） | 記事を編集 | 作成フローの「記事の生成・編集」 |

- 状態判定は既存 `ProjectArticleMap` の規則を共有化する。初版で意味を変えない。
- 現状の「作成完了」はexport到達で判定している。公開済みやエクスポート成功とは区別する。
- `openArticle(projectId, articleId, origin)` として、所属プロジェクトを読み込んでから記事を有効化する。
- 完了記事は最終工程がexportでも記事詳細へ開く。未着手・作業中もタイトルからは詳細を開け、作成操作からは既存フローを直接再開できる。
- originはホーム／記事一覧／プロジェクト詳細を保持する。戻るラベルと戻り先を一致させる。
- 記事切り替えや工程移動でもoriginを維持する。記事一覧に戻ったときは検索、フィルター、読み込み済み件数、スクロール位置を復元する。
- 読み込み失敗時は元画面に留まり、エラーと再試行を表示する。
- 読み込み中の二重操作と遷移競合は既存の操作キュー・navigationRequestRefに合わせて防ぐ。

## データ取得と責務

一覧のために全プロジェクトの動画・Slide・本文を復元しない。SQLiteから軽量な一覧DTOを取得する。

- `ArticleListItem`: articleId、projectId、title、projectTitle、createdAt、workflowの表示に必要な情報。
- `listArticles({ query, status, limit, cursor })` → items、絞り込み後のtotal、nextCursor。
- 順序は `created_at DESC, id DESC` とし、同一作成日時でも安定させる。cursorもこの組を使う。
- ホームは同じ取得口を `limit: 3` で利用。記事一覧は `limit: 30`。
- 状態の判定条件はDTO契約として定義し、SQLのフィルターとUI表示が一致するようテストする。
- 記事やプロジェクトの削除はDBの実データを参照して反映する。独立した一覧用データを二重保存しない。
- 一覧に戻る際に再取得し、タイトル変更・作成・削除・工程進行を反映する。取得失敗は空状態と分ける。

変更箇所の想定:

| 場所 | 変更 |
| --- | --- |
| `src/components/AppHeader.tsx` | 記事ナビ、狭幅ナビ |
| `src/app/App.tsx` | articlesルート、横断記事オープン、戻り先管理 |
| `src/features/home/HomePage.tsx` | 最新3件の表示 |
| `src/features/article/ArticlesPage.tsx`（新規） | 検索・フィルター・一覧 |
| `src/features/article/ArticleDetailPage.tsx`（新規） | 閲覧、編集・工程選択・所属プロジェクトへの導線 |
| `src/features/article/components/ArticleListRow.tsx`（新規） | 一覧とホームの共通行 |
| article用hook、storage、types、schemas | 一覧取得、状態、DTO検証 |
| Tauri DB層・コマンド登録 | 全記事の軽量一覧クエリ |

既存の未コミット変更が広範囲にあるため、実装時は現在のSQLite・workspaceの変更を前提に差分を追加する。

## 空状態・異常時

- 記事0件: 「まだ記事がありません。動画を読み込むと、記事の作成を始められます。」記事一覧では「ホームで動画を読み込む」を表示する。
- 検索0件: 「条件に一致する記事がありません」と「条件をクリア」。
- 読み込み中: 3行程度のスケルトン。失敗時: 欄内に再読み込みボタン。
- ホームの記事欄とプロジェクト欄は個別の読込状態を持ち、一方の失敗でも他方を利用できる。
- 表示後に削除された記事: 元画面に留まり、一覧を更新する。
- 元動画やデータの問題: 完了状態と別の問題として扱い、既存のエラー処理に沿って案内する。

## 受け入れ条件

1. 3つのタブを広い幅・狭い幅の両方で操作できる。
2. 異なるプロジェクトの記事が同じ一覧に並び、正しい記事を開ける。
3. ホームは新規作成日時順の最大3件で、閲覧だけでは順序が変わらない。
4. 記事タイトルから閲覧画面を開ける。作成・編集操作は適切な工程へ遷移する。
5. 戻る操作で遷移元と検索・スクロール状態を復元できる。
6. 検索・フィルター・ページ送りを組み合わせても重複や取りこぼしがない。
7. 空、取得失敗、削除済み、連続クリックを区別して扱える。
8. 記事詳細から編集・所属プロジェクト詳細へ移動でき、編集後は同じ記事の閲覧画面へ戻れる。

実装順はDB一覧取得、横断遷移、記事一覧、閲覧画面と編集導線、ホーム欄、狭幅ナビ、検証とする。
