# Video Notes — 実装仕様書

> この文書は初期構想です。保存方式を含む現行仕様は [SQLite永続化設計](./sqlite-detailed-design.md) を参照してください。ここに残る`project.json`の構成図は履歴であり、実装要件ではありません。

## 1. プロダクト概要

### 1.1 アプリ名

**Video Notes**

### 1.2 目的

カンファレンス、オンライン授業、大学講義、ウェビナー、社内勉強会などの動画を入力し、動画内のスライド切り替わりを検出して、各スライド画像と対応する発話テキストを並べた「記事形式のノート」を生成するデスクトップアプリケーション。既定では完全ローカルで処理し、ユーザーが明示的に選択した場合のみ、本文生成にユーザー所有のOpenAI APIキーを利用できる。

最終成果物の中心は文字起こし単体ではなく、以下のような構造を持つ読み物。

```text
Title

[Slide Image]

Section text...

[Slide Image]

Section text...

[Slide Image]

Section text...
```

動画を見返さなくても、スライドと発話内容を記事として追える状態を作る。

### 1.3 想定ユースケース

- 技術カンファレンス
- セミナー
- ウェビナー
- オンライン授業
- 大学講義
- プレゼンテーション録画
- 社内勉強会
- 製品デモ
- スライド共有を伴う会議録画

### 1.4 最重要要件

- 動画データをクラウドへ送信しない
- OCRと文字起こしはローカルモデルを既定とし、ユーザーが明示選択した場合のみOpenAI APIを利用する
- 本文生成、文字起こし、OCRの各処理で、ユーザーが明示的に選んだ場合のみOpenAI APIを利用する
- OpenAI利用時は、選択した処理に必要なデータだけを送信する。文字起こしでは音声、OCRでは代表画像、本文生成では文字起こしとOCRテキストを送信し、動画やローカルファイルパスは送信しない
- OpenAI APIキーはユーザー自身のキーをmacOS Keychainへ保存し、プロジェクトやログへ記録しない
- ローカルモデルを選べば、必要モデルの取得後は完全オフラインで処理可能
- M1 Mac / 16GB Unified Memoryで実用的に動作する
- ユーザーがffmpeg / whisper.cpp / llama.cppを個別インストールしなくてよい
- clone後にほぼ自動で開発環境を立ち上げられる
- 最終成果物としてHTML記事を生成できる

# 4. 記事本文生成方針

## 4.1 基本

記事本文 `body` は、補正済み文字起こしをベースに生成する。

初期バージョンでは過度な要約を避ける。

目的:

```text
spoken transcript
↓
読みやすい文章
```

であり、

```text
spoken transcript
↓
短い要約
```

ではない。

## 4.2 Pass分離

LLM処理は最低2段階に分ける。

### Pass 1: Transcript Correction

OCR情報を使ってWhisper誤認識を訂正。

### Pass 2: Article Formatting

補正済みTranscriptを記事として読みやすく整形。

この2処理を混ぜない。

## 4.3 Article Formatting Rules

許可:

- フィラー除去
- 句読点追加
- 適切な段落分け
- 明らかな言い直しの整理
- 重複表現の軽微な整理

禁止:

- 発話していない事実の追加
- 大幅な要約
- 主張の変更
- スライドだけを根拠にした文章追加

# 25. Cache Policy

```text

+
crop unchanged

boundary unchanged
→ audio/transcript再利用

corrected transcript unchanged
→ article formatting再利用
```

各cacheにはinput hashを持たせる。


```text

↓

↓
```

# 42. Security / Privacy

必須:

- ローカルプロバイダーを選んだ処理では動画、音声、画像、OCR結果、Transcriptを外部送信しない
- OpenAIプロバイダーを選んだ処理では、その処理に必要な入力だけを送信する
- OCRでOpenAIを選んだ場合は代表画像をOpenAIへ送信することをUIで明示する
- ローカルプロバイダーのAI inferenceはlocalhostのみ
- Telemetryなしをデフォルト
- HTML exportにも外部trackingを入れない

Network利用は原則:

```text
sidecar/model download
```

のみ。

# 49. Design Decisions

## Tauriを採用

理由:

- M1 16GBでUI runtimeのmemory overheadを抑えたい
- heavy processingはsidecar
- Node.jsをアプリruntimeに必須としない
- UI / orchestrationはTypeScript中心
- Rust layerを薄くできる
- 配布サイズを抑えやすい

## whisper.cpp + llama.cpp

### whisper.cpp

Speech-to-Text専用。

### llama.cpp

- OCR / VLM
- Transcript correction
- Article formatting

に利用する。

無理に1runtimeへ統一しない。

# 51. 最終方針

Video Notesは文字起こしツールではなく、

**「動画を、ローカル処理を基本とするスライド画像付きの記事へ変換するアプリ」**

として設計する。

```text
Conference / Lecture Video
↓
Slide Detection
↓
Speech Transcription
↓
Slide OCR
↓
Transcript Correction
↓
Article Formatting
↓
HTML Article
```

処理の責務:

```text
ffmpeg
→ media processing

whisper.cpp
→ speech transcription

llama.cpp
→ OCR
→ transcript correction
→ article formatting

Tauri + TypeScript
→ GUI
→ orchestration
→ review
→ HTML generation
→ export
```

最重要な完成形:

```text
動画を入力
↓
ローカル処理
↓
画像とテキストが交互に並ぶ読みやすい記事
↓
index.htmlとして持ち出せる
```

ユーザーがローカルプロバイダーを選んだ処理では、動画・音声・スライド画像・文字起こし・OCR結果をMacの外へ出さない。OpenAIを明示選択した場合は、文字起こしでは音声、OCRでは代表画像、本文生成では文字起こしとOCRテキストをOpenAI APIへ送信する。
