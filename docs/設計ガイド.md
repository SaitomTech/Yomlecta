# Video Notes 設計ガイド

この文書は、[初期構想.md](./初期構想.md)に記載した処理パイプラインを、変更しやすいコード構造へ落とし込むためのガイドです。

Video Notesは、動画を入力として、スライド画像と発話内容が交互に並ぶ記事を生成するローカル優先のデスクトップアプリです。本文生成、文字起こし、OCRは、ユーザーが明示選択した場合に限りユーザー所有のOpenAI APIキーを利用できます。OCRの既定値はmacOS標準のApple Visionによるオンデバイス処理です。画面、パイプライン、外部プロセス、保存データの責務を分離し、処理の一部だけを再実行できる構造を優先します。

> 保存層の現行仕様は [SQLite永続化設計](./sqlite-detailed-design.md) です。この文書に残る`project.json`の記述は設計履歴として扱い、実装の判断には使用しません。旧JSONを読み込む互換層はありません。

> 記事状態の現行仕様は [記事状態の正本統一設計](./article-state-single-source-design.md) を参照してください。Projectの記事entryをmetadata/loadedに分け、記事内容の展開・同期は行いません。

## 1. 設計の基本方針

### 1.1 機能単位で分ける

画面の種類ではなく、ユーザーが行う作業単位でコードをまとめます。

```text
Import
Crop & Trim
Slide Detection
Processing
Transcription
OCR
Content Processing
Article
Export
```

各機能は、ページ、表示部品、状態管理、機能固有の型・純粋関数を同じディレクトリに置きます。

### 1.2 `App.tsx`は組み立て役にする

`App.tsx`に以下を書かないでください。

- ファイル選択の実装
- ffmpeg / ffprobeの呼び出し
- AIモデルとの通信
- 大きな画面レイアウト
- プロジェクトデータの変換ロジック

アプリの入口では、現在の画面やアプリ全体のProviderを組み立てるだけにします。

現在の入口は画面遷移とプロジェクト状態の組み立てだけを担当します。

```tsx
import { CropPage } from '../features/crop/CropPage'
import { ImportPage } from '../features/import/ImportPage'

function App() {
  // routeとProjectを管理し、各Pageへ渡す
}
```

### 1.3 TypeScriptがオーケストレーション、RustがOS境界

仕様書の方針に合わせ、AIやパイプラインの判断はTypeScript側に置きます。

Rust側は次に限定します。

- Tauri command
- sidecarの起動・停止・権限
- ファイルシステム連携
- OS固有処理
- プロセスのライフサイクル

Rust側にOCR、文字起こし、プロンプト、記事整形のロジックを実装しません。

### 1.4 記事状態を一つにする

保存対象の正本はSQLiteの正規化テーブルです。画面の`Project.articles`は一覧用metadataまたは読み込み済みArticleを保持し、詳細を読み込むのは一件だけです。activeArticleはそのentryを返すselectorで、独立したstateや記事フィールドのコピーを持ちません。

映像区間とOCRは`Article.visualSegments`、発話と本文は`Article.blocks`、章・要約・翻訳は`Article.document`に置きます。タイトルは`Article.title`のみです。表示用の`ArticleBlockView`はその都度結合し、保存しません。

純粋な更新関数は`lib/project/article.ts`、保存処理は`articleOperations.ts`、状態の置換と操作の直列化は`createProjectWorkspace`の責務です。操作ごとに対象のTauri commandへ反映し、保存成功後にstateを更新します。詳細とrevisionは同じ読み込みtransactionで取得します。

### 1.5 ステージを再実行可能にする

各処理ステージは、入力が同じなら同じ結果を再利用できるようにします。

```text
original source + article range + crop
  → frame / hash cache

boundaries
  → audio / transcript cache

representative image
  → OCR cache

transcript + OCR
  → article formatting cache
```

キャッシュには入力ハッシュとモデル情報を持たせ、モデルや入力が変わった場合だけ再処理します。

### 2.1 sidecarの取得と同梱

`src-tauri/tauri.conf.json`の`bundle.externalBin`に`binaries/ffmpeg`、`binaries/ffprobe`、`binaries/whisper-cli`、`binaries/llama-server`、`binaries/apple-vision-ocr`を登録しています。Tauriはビルド対象のtarget tripleを末尾につけたファイルをsidecarとしてbundleするため、macOS Apple SiliconではApple VisionのSwift helperもsidecarとして同梱します。

```text
src-tauri/binaries/ffmpeg-aarch64-apple-darwin
src-tauri/binaries/ffprobe-aarch64-apple-darwin
src-tauri/binaries/whisper-cli-aarch64-apple-darwin
src-tauri/binaries/llama-server-aarch64-apple-darwin
src-tauri/binaries/apple-vision-ocr-aarch64-apple-darwin
```

これらはリポジトリへ大きなバイナリを直接コミットせず、`bun run dev`または`bun run build`の前処理で`bun run prepare:sidecars`が不足時だけ取得します。取得後は固定リリースのSHA-256を検証し、実行権限を付与します。llama.cppは複数のdylibを必要とするため、`src-tauri/binaries/llama-runtime`へランタイムライブラリを展開し、開発時と`.app`内の双方から参照できるrpathを`llama-server`へ設定します。アプリ実行時の呼び出しは`src/lib/tauri/sidecar.ts`に閉じ込め、動画固有の変換は`src/lib/media`から利用します。

Apple Vision helperは`src-tauri/vision-ocr/main.swift`から`swiftc`でビルドします。VisionのOCRモデル自体はmacOSが提供するため、アプリ側で追加のOCRモデルをダウンロードしません。

現在の取得元はffmpeg / ffprobeがmacOS Apple Silicon向け静的ビルドを提供するMartin Riedlのビルドサーバー、whisper-cliとllama-serverがmacOS Apple Silicon向けビルドを提供する固定GitHub Releaseです。いずれも`scripts/prepare-sidecars.ts`でURLとSHA-256を固定しています。リリースを更新するときは、同ファイルのURL・リリース番号・SHA-256を同時に更新し、ライセンスと再配布条件も確認します。

空の機能ディレクトリを最初から大量に作る必要はありません。機能を実装するタイミングで、その機能のディレクトリとファイルを追加します。

## 3. 各ディレクトリの責務

### `src/app`

アプリ全体の起動点と画面の組み立てを置きます。

- `App.tsx`
- 将来のProvider
- 将来の画面遷移・ルート選択

機能の詳細には依存しますが、Tauriプラグインを直接呼び出しません。

### `src/components`

複数の機能・画面から使うUI部品を置きます。

現在は、ヘッダーとワークフローステップをここに置いています。

ルール:

- ビジネスロジックを持たない
- `features/*`へ依存しない
- Tauri APIを直接呼び出さない
- 汎用化できない機能固有部品は各featureへ置く

### スタイリング

Tailwind CSS v4を標準とし、Viteプラグインで読み込みます。

- 画面・部品のスタイルはTailwindのutility classを`className`へ書く
- `src/index.css`はTailwindの読み込みを基本とする
- 機能ごとのCSSファイルは新設しない
- 同じスタイルが繰り返される場合は、まずUIコンポーネント化を検討する
- Tailwindで表現できない外部ライブラリ固有の調整だけ、例外的にCSSを追加する

### `src/features`

ユーザー向けの機能を置きます。各featureは小さなアプリケーションとして扱います。

標準形:

```text
features/<feature>/
├─ components/
├─ hooks/
├─ <Feature>Page.tsx
├─ types.ts
└─ utils.ts または lib/
```

### `src/lib`

Reactから独立した処理と、外部システムとの接続を置きます。

#### `lib/tauri`

TauriプラグインやTauri commandの薄いラッパーです。

例:

```ts
export async function pickVideoPath(): Promise<string | null>
```

featureから`@tauri-apps/plugin-*`を直接importせず、可能な限りこの層を経由します。これによりブラウザ上のテストとTauri実装を分離できます。

#### `lib/media`

- ffprobe呼び出し
- ffmpeg呼び出し
- 動画の時間範囲切り出し
- フレーム抽出
- 音声抽出
- 動画メタデータの変換

#### `lib/hashing`

- dHash
- pHash
- Hamming distance
- 入力ハッシュ

#### `lib/models`

- モデルの保存先
- 初回ダウンロード
- 途中ファイルの破棄
- SHA-256検証
- ダウンロード進捗

モデル本体はリポジトリへ含めず、`AppLocalData/models`へ保存します。モデルの取得は処理開始時に必要なものだけ行い、完了後は同じモデルを再利用します。

#### `lib/whisper` / `lib/llama`

- sidecarまたはlocalhost serverの起動
- healthcheck
- リクエスト送信
- 結果のparse
- 終了処理

プロンプトの組み立ては`lib/llama`または利用するfeatureの責務とし、Rustには置きません。

#### `lib/pipeline`

ステージの順序、進捗、キャンセル、再開、キャッシュ判定を管理します。

### `src/types`

複数featureから参照するドメイン型を置きます。

次の型をここで管理します。

- `Project` / `ProjectArticleEntry` / `Article` / `ArticleMetadata`
- `MediaSource`
- `MediaMetadata`
- `CropRegion`
- `SlideData`
- `SlideBoundary`
- `TranscriptSegment`
- `ArticleSection`
- `VideoNotesArticle`
- `ProcessingJob`

ReactのProps専用型や、そのfeatureだけで完結する一時状態は各featureの`types.ts`に置きます。

### `src/schemas`

Zodによる実行時検証を置きます。

- `projectSchema`
- `mediaMetadataSchema`
- `slideSchema`
- `articleSchema`
- `jobSchema`

JSONを読み込むときは、型アサーションだけで済ませず、必ずschemaで検証します。

### `src-tauri`

Tauri固有のOS境界です。

```text
React / TypeScript
  ↓ lib/tauri
Tauri command / plugin
  ↓
filesystem / sidecar / OS
```

sidecarの引数やプロセス管理に必要な処理はRustへ置けますが、アプリケーションの業務ルールはTypeScript側に残します。

## 4. 依存方向

依存方向は次を基本とします。

```text
app
 ├─ features
 └─ components

features
 ├─ components
 ├─ lib
 ├─ types
 └─ schemas

components
 └─ 共通の型・スタイルのみ

lib
 ├─ types
 └─ schemas

types
 └─ 他のUI層・Tauri層へ依存しない
```

避ける依存:

- `components` → `features`
- `types` → React / Tauri
- `lib` → Reactコンポーネント
- `features` → `src-tauri`の内部ファイル
- feature間の直接的な循環依存

別featureの機能が必要になった場合は、共通の`lib`、`types`、`schemas`へ責務を移します。

## 5. Import機能の現在の設計

現在のImport機能は、次のように分割されています。

```text
ImportPage
 ├─ AppHeader
 ├─ WorkflowBar
 ├─ VideoDropZone
 ├─ SelectedVideoSummary
 └─ import footer action

useVideoPicker
 ├─ Tauri native dialog
 ├─ drag & drop
 └─ extension validation

lib/tauri/dialog
 └─ @tauri-apps/plugin-dialog の薄いラッパー
```

`ImportPage`はレイアウトの組み立てに集中し、ファイル選択の非同期処理は`useVideoPicker`へ分離しています。

Importでは、選択した動画のファイル名・拡張子・サイズに加えて、sidecarのffprobeで長さ・解像度・FPSを取得します。HTML videoの`canplay`とffprobeの両方が成功した場合だけREADYとし、壊れたファイルや拡張子だけを書き換えたファイルはCROPへ進めません。

動画のメタデータはプロジェクト動画を`Project.videos`、記事ごとの解析設定を`Article.sourceRange` / `Article.crop`に保持し、正本はTauriの`AppLocalData/library/library.sqlite`へ保存します。プロジェクト動画は追加時に管理領域へ1本だけコピーまたはダウンロードし、記事は元動画を参照して範囲とCropを適用します。画面DTOの復元時だけSQLiteの動画・asset行から`Article.inputMedia`を組み立てます。

記事候補の作成モーダルでは元動画をプレビューし、複数の開始・終了位置をまとめて指定します。共通のCropを初期値として設定できますが、各記事の作成フローでも個別に調整できます。確定時は範囲・Crop設定だけを記事へ保存し、記事単位の動画コピーは作成しません。

記事の作成フローには最初に`範囲を調整`ステップを置きます。Slide Detection、文字起こし、OCR、記事生成は元動画へ記事の範囲・Cropを適用して実行します。範囲やCropを変更した場合は、該当記事だけの後続結果とキャッシュを無効化します。ほかの記事候補や元動画自体は変更しません。

## 6. 状態管理

### 6.1 画面内の一時状態

次のような状態はfeature内のhookで管理します。

- ダイアログを開いているか
- ドラッグ中か
- 選択中か
- 入力エラー
- 選択したファイルの表示状態

### 6.2 プロジェクト状態

複数画面から参照する保存対象は`useProjectWorkspace`のProject stateに集約します。記事の編集・保存はprojectId/articleIdを明示し、workspaceのキュー内で最新の記事参照を取得します。対象が変わった解析結果は拒否します。ダイアログや入力途中の値はfeature内に置き、外部state managerは導入しません。

## 7. パイプライン設計

処理ステージは次の順番です。

```text
probe
  → range + crop (processing filter)
  → detect-slides
  → extract-audio
  → transcribe
  → ocr
  → format-article
  → export
```

各stageは次の性質を持たせます。

- 入力と出力を型で定義する
- 進捗をJob Managerへ通知する
- キャンセル可能にする
- 失敗理由を`AppErrorCode`へ変換する
- 入力ハッシュが一致すればcacheを使う
- stage単位で再実行できる

AIモデルは同時に常駐させません。

```text
Whisper load → transcription全部 → unload
OCR load → OCR全部 → unload
Text LLM load → article formatting → unload
```

## 8. エラーと境界

ユーザー向けメッセージとデバッグ情報を分けます。

```ts
type AppError = {
  code: AppErrorCode
  message: string
  detail?: string
  cause?: unknown
}
```

例えば、UIには「動画を読み込めませんでした」と表示し、ログにはffprobeの終了コードやstderrを残します。

外部通信はモデル・sidecarの取得時と、OpenAIプロバイダーを明示選択した処理に限ります。OpenAIの文字起こしでは音声、OCRでは代表画像、本文生成では文字起こしとOCRテキストを送信します。ユーザーがローカルプロバイダーを選んだ処理の入力は外へ送信しません。

## 9. 実装ルール

- 1ファイルの責務を1つにする
- ページコンポーネントは部品を組み合わせる
- 非同期処理と状態遷移はhookまたはlibへ分ける
- `utils.ts`を無制限の寄せ集めにしない
- Tauri APIは`src/lib/tauri`に閉じ込める
- ドメイン型はUI型と分ける
- SQLiteから復元した画面DTOはZod検証を通す
- AI結果はraw結果を破棄せず、補正前後を保存する
- 外部URL、CDN、外部フォントを成果物へ持ち込まない
- 変更後は`bun run build`と`bun run lint`を実行する
