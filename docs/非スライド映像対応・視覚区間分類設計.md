# 非スライド映像対応・視覚区間分類設計

作成日: 2026-09-27
状態: 実装済み

## 目的

講演動画の「スライド」「登壇者・観客などの非スライド映像」「自動判定で確定できない映像」を区別し、映像編集上の切り替えと記事の本文構造を分離する。

人物映像の発話は捨てず、前後のスライドを基準にした記事ブロックへ統合する。動画全体が非スライドの場合だけ、画像なしの記事ブロックを作る。

## 区間種別

| 種別        | 意味                                           | OCR        | 記事での扱い                     |
| ----------- | ---------------------------------------------- | ---------- | -------------------------------- |
| `slide`     | スライドが主要な映像                           | 実行       | 画像付き記事ブロックのアンカー   |
| `non-slide` | 登壇者・観客・会場などの記事画像に使わない映像 | 実行しない | 前後のアンカーへ発話を統合       |
| `unknown`   | 自動判定が不確実                               | 実行       | 取りこぼし防止の画像付きアンカー |

スライドと人物が同時に映る状態は別種別にせず、`slide` に `personLayout` を付ける。

```ts
type VisualSegmentKind = 'slide' | 'non-slide' | 'unknown'
type PersonLayout = 'none' | 'inside-crop' | 'outside-crop' | 'both' | 'dominant'
```

`overrideKind` がある場合は自動判定より優先する。

```ts
effectiveVisualKind(segment) = segment.overrideKind ?? segment.autoKind
```

## 全体処理

```text
Crop領域を500ms間隔で9x8グレースケール化
  ↓
dHash＋平均輝度差から候補境界を検出
  ↓
候補境界から仮区間を作成
  ↓
5秒以上続く局所安定区間を仮区間から切り出す
  ↓
区間内のCrop最長安定区間を計算
  ↓
全画面サンプルで顔・人体・顔ランドマークを検出
Crop代表画像で文字領域を検出
  ↓
slide / non-slide / unknownを分類
  ↓
連続するnon-slideを結合
  ↓
種別に応じた代表画像を作成
  ↓
手動確認・上書き
  ↓
記事ブロックを構築し、文字起こしを時間順に割り当て
```

境界生成にはCrop信号だけを使う。全画面差分は計算しない。人物検出だけは、Crop外の登壇者やワイプを見落とさないよう全画面画像を使う。

## 境界検出とCrop安定度

隣接サンプルの距離は次の合計とする。

```text
distance = hammingDistance(dHash) + round(abs(luma差) / 8)
```

境界条件:

```text
previous → current >= threshold
current → next <= max(2, floor(threshold / 2))
直前の境界から1.5秒以上
```

初回の境界検出は、差分が徐々に変化する切り替わりを取りこぼすことがある。人物・文字の検出前に、仮区間内の安定pairが5秒以上連続する部分を独立した区間へ分割し、動いている前後の映像と別に分類する。分割後も1.5秒未満の区間は作らない。

区間分類では、安定pairの全体割合ではなく、連続した最長安定時間を使う。

```text
cropLongestStableRunRatio
  = 最長連続安定時間 / 区間内のサンプル時間
```

離れた静止部分を合算して、途中に大きな動きがある映像をスライドと誤認することを防ぐ。旧 `cropStableRatio` は既存解析結果の読取互換だけに残し、新しい解析結果には保存しない。

## Apple Visionによる証拠

`apple-vision-ocr` sidecarは次のモードを持つ。

- `--detect-people`: `VNDetectFaceLandmarksRequest` と `VNDetectHumanRectanglesRequest`
- `--detect-text-regions`: Crop画像への `VNDetectTextRectanglesRequest`

人物サンプル数:

| 区間長   | サンプル位置                |
| -------- | --------------------------- |
| 2秒未満  | 25% / 75%                   |
| 2〜15秒  | 20% / 50% / 80%             |
| 15秒以上 | 10% / 30% / 50% / 70% / 90% |

顔と人体はIoUで同一対象を追跡する。顔ランドマークは顔輪郭・目・眉・鼻・口の正規化座標を署名にし、同じ顔のサンプル間変化を計算する。顔認証・個人同定・属性推定は行わない。

Crop文字検出では認識文字列を使わず、文字領域数と面積だけをスライドの正の証拠にする。

主な判定根拠:

```ts
type VisualClassificationEvidence = {
  samplesAnalyzed: number
  cropLongestStableRunRatio?: number
  cropLongestStableRunMs?: number
  cropMotionMedian: number
  textRegionCount?: number
  textRegionAreaRatio?: number
  facePresenceRatio: number
  humanPresenceRatio: number
  largestFaceAreaRatio: number
  largestHumanAreaRatio: number
  personOutsideCropRatio: number
  personCenterMotionMedian: number
  personAreaChangeMedian: number
  personBoxIouMedian: number
  faceLandmarkMotionMax?: number
}
```

## 自動分類の優先順位

判定は、信頼度の異なる証拠を一つのスコアへ混ぜず、次の順序で行う。

1. 安定したCropの外側に小さな人物がいる → `slide`
2. 継続した人物検出があり、顔内部に生きた動きがある → `non-slide`
3. Cropが安定し、人物検出と顔・人物矩形の動きがない → `slide`
4. 文字領域があり、Cropに最低限の連続安定区間がある → `slide`
5. 継続した人物検出があり、人物矩形が移動・拡縮している → `non-slide`
6. 人物なしでCropが安定 → `slide`
7. 小さな人物がいてCropが安定 → `slide`
8. それ以外 → `unknown`

顔ランドマークの変化は0.05以上を動きとして扱う。安定した静止区間では、顔・人物矩形が動いていない人物写真も `slide` にする。人物矩形モーションは集合写真や絵画で追跡対象が飛ぶため補助証拠とし、「文字＋安定Crop」より後に評価する。

人物ありは全サンプルの60%以上で顔または人体が検出された場合に限る。5点中2点だけの反応は人物誤検出として無視する。

現在の分類器バージョンは `visual-rules-v12-stable-hold-refinement`。

## 代表画像

- `slide` / `unknown`: Crop代表画像
- `non-slide`: 全画面代表画像

代表時刻は区間中央を基本とし、極端に短い区間では終端から200ms以上内側へ寄せる。分類用一時画像はrun終了時に必ず削除する。

## 記事ブロック

`VisualSegment` は映像上の区間、`ArticleBlock` は記事の本文・画像単位であり、1対1とは限らない。

```ts
type ArticleBlock = {
  id: string
  index: number
  visualSegmentIds: string[]
  imageSegmentId?: string
  startMs: number
  endMs: number
  transcript?: VisualSegment['transcript']
}
```

構築規則:

1. `slide` / `unknown` をアンカーにする。
2. アンカー間の `non-slide` は原則として直前のアンカーへ付ける。
3. `[slide A][non-slide][slide A]` のようにCrop hashが同じなら1ブロックへまとめる。
4. 先頭の `non-slide` は次のアンカー、末尾は前のアンカーへ付ける。
5. アンカーがない動画は画像なしの1ブロックにする。

記事ブロックIDは `imageSegmentId`、画像なしなら先頭の `visualSegmentId` と一致させる。これにより既存のUI・編集APIで表示ホスト区間IDを安定して利用できる。

文字起こしは動画全体を対象にし、時間の重なりが最大の記事ブロックへ割り当てる。長い時刻なし結果が複数ブロックを覆う場合は、時間比率と自然な句読点位置で分割する。

OpenAI音声チャンクは記事ブロックごとには分けず、60秒を目標、15分を上限としてブロック境界に揃える。

## 下流処理

- OCRは `ArticleBlock.imageSegmentId` が参照する区間だけを対象にする。
- 本文・要約・章立て・翻訳・書き出しは記事ブロック表示を入力にする。
- 画像なしブロックは発話だけで本文を生成し、HTML等では1カラム表示にする。
- `unknown` は取りこぼし防止のため `slide` と同様にOCR・画像付き記事の対象にする。
- 自動分類の失敗はパイプラインを止めず、対象区間を `unknown` にする。

## 永続化

SQLiteでは次を正本とする。

```text
articles
├─ visual_segments
│  ├─ ocr_results
│  └─ visual_segment_ocr_selections
├─ article_blocks
│  └─ article_block_segments ── visual_segments
└─ documents
```

- 種別は `visual_segments.auto_kind` / `override_kind` に保存する。
- 分類根拠だけを `classification_json` に保存する。
- 記事本文は `article_blocks.transcript_json` に保存する。
- `article_block_segments.segment_id` の `UNIQUE` で二重所属を防ぐ。
- `analysis_runs.kind` は新規解析で `visual_segmentation` を使い、旧 `slide_detection` は読取互換として残す。

migrationでは旧 `slides` を同じIDの `visual_segments` と `article_blocks` に分け、OCR採用結果と本文を引き継ぐ。プロジェクトversionは12。

## UI

- タイムラインを `slide`、`non-slide`、`unknown` で色分けする。
- 一覧で種別を手動上書きできる。
- `unknown` は「要確認」と表示するが、記事生成はブロックしない。
- 自動検出のしきい値・サンプル間隔は内部設定とし、ユーザー操作には公開しない。

## 失敗時の扱い

| 失敗                   | 扱い                        |
| ---------------------- | --------------------------- |
| Cropサンプリング       | 検出全体を失敗              |
| 人物検出画像の一部抽出 | 対象区間を `unknown`        |
| Apple Vision人物検出   | 対象区間を `unknown`        |
| 文字領域検出           | 文字証拠なしで継続          |
| 代表画像抽出           | 保存を中止し候補assetを削除 |
| revision競合           | transactionをrollback       |

## 回帰テスト

- 人物矩形が静止していても顔ランドマークが動けば `non-slide`。
- 背景に文字がある登壇者も、顔内部モーションを優先して `non-slide`。
- 集合絵の人物矩形が飛んでも、文字と安定Cropがあれば `slide`。
- 離れた安定pairの合計ではなく、最長連続安定区間で判定する。
- 5点中2点だけの人物検出を無視する。
- 連続する `non-slide` は人物構図が変わっても結合する。
- 無音区間は本文生成完了条件に含めない。
- 全編 `non-slide` は画像なしの記事として書き出せる。

## 対象外

- 登壇者と観客の識別
- 顔認証・個人同定・属性推定
- 話者ダイアリゼーション
- ライブデモやコード編集画面の専用分類
